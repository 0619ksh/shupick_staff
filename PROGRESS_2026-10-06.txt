SHOEPICK 직원용 앱 진행사항

1. 프로젝트 구성 및 공통 정책
- 이전 HTML 직원용 화면을 Flutter 직원용 앱으로 구현했습니다.
- 앱 이름을 SHOEPICK으로 통일했습니다.
- 고객용 shupick 프로젝트의 Firebase Authentication, FastAPI, MySQL shupick_v2를 공유하는 구조입니다.
- 서버에서 허용한 직책과 소속 지점만 앱에 표시합니다.
- 교환 기능은 운영 계획에서 제외하고 직원 앱의 교환 화면 분기와 문구를 제거했습니다.

2. 직원 인증과 직원 등록
- Firebase 이메일/비밀번호 로그인 및 로그인 상태 복원을 연결했습니다.
- 로그인 후 MySQL 직원 정보, 사용 가능한 직책, 현재 소속 지점을 조회합니다.
- 직원 등록 화면에서 이메일, 비밀번호, 비밀번호 확인, 이름, 소속 구분, 소속 지점, 직책을 입력합니다.
- 대리점 소속은 서울 25개 자치구 중 지점을 선택하며, 본사 선택 시 소속 지점 입력이 비활성화됩니다.
- 등록 시 Firebase 계정 생성과 FastAPI를 통한 MySQL 직원·직책·지점 배정 저장을 연결했습니다.
- 현재 테스트 정책은 이메일 인증과 관리자 승인 없이 즉시 활성화입니다.
- 계정 삭제 및 직원 권한 변경 화면은 아직 구현하지 않았습니다.

3. 직책별 업무
- 대리점 직원: 주문 입고 확인, 픽업 결제 코드 확인, 고객 상품 수령 완료, 반품 상태 조회, 현재 보관 재고 조회.
- 대리점장: 대리점 입고·수령·반품 업무와 날짜별 보관 재고 조회.
- 본사 사원: 주문·배송 조회와 발송 처리, 고객 목록 및 구매·반품 내역 조회, 문의 확인·답변, 반품 검수, 본사 재고, 구매 품의 작성·상신.
- 본사 팀장: 1차 구매 품의 승인·반려 및 재고 조회.
- 본사 이사: 최종 구매 품의 승인·반려 및 재고 조회.
- 본사 임원: 최근 28일 판매 분석, 재고 및 결재 현황 조회.
- 고객 수령 절차는 QR 스캔에서 픽업 결제 코드 확인 방식으로 변경했습니다.
- 고객 문의 답변은 본사 사원 메뉴의 고객 관리에서 수행하며 서버의 SUPPORT_MANAGE 권한이 필요합니다.

4. 대시보드 집계와 알림
- 직책별 카드와 업무 알림을 서버 조회 결과에 연결했습니다.
- 업무 알림을 누르면 해당 업무 화면으로 이동합니다.
- 대리점 직원과 점장은 선택한 소속 지점의 주문·반품·보관 수량을 집계합니다.
- 주문·반품·문의·품의 요약은 각 API의 최근 100건 조회 범위이며 전체 기간 총계가 아닙니다.
- 임원 판매 분석 기본 범위는 최근 28일입니다.
- 재고 부족 기준은 가용 수량이 목표 수량의 30% 미만인 제품 옵션입니다.
- 주문·반품·재고 중 한 API가 실패하면 대시보드 전체가 사라지던 문제를 수정했습니다.
- 조회에 성공한 집계는 표시하고, 실패한 항목은 숫자 0 대신 '—'와 실패 안내를 표시합니다.
- 대리점 대시보드는 로딩·실패 상태에서도 카드 구조와 빠른 업무 진입 버튼을 유지합니다.

5. 최신 레이아웃 수정
- 태블릿 폭 700~1199px에서는 업무 메뉴를 상단에 배치해 본문 너비를 확보했습니다.
- 1200px 이상에서는 왼쪽 업무 메뉴를, 700px 미만에서는 서랍 메뉴를 사용합니다.
- 상단에는 직원 정보, 직책·지점 선택, 로그아웃을 배치했습니다.
- 대리점 직원은 '대리점 업무 대시보드', 점장은 '지점 운영 대시보드' 제목을 표시합니다.
- 대시보드에 빠른 업무 버튼을 추가했습니다.
- 요약 카드의 고정 높이를 제거해 큰 글자에서도 내용에 맞춰 늘어나도록 수정했습니다.
- 메뉴 영역이 작은 화면 높이에서도 스크롤되도록 수정했습니다.
- 날짜 선택 영역은 너비에 따라 줄바꿈하도록 수정했습니다.
- 판매 그래프는 날짜 칸의 최소 너비와 가로 스크롤을 적용해 오버플로우를 수정했습니다.
- 로그인 브랜드 영역은 좁은 화면에서 줄바꿈하도록 수정했습니다.

6. 검증 결과
- flutter analyze: No issues found.
- flutter test: 20개 테스트 모두 통과.
- 화면 크기 360x640, 800x1024, 1024x600, 1280x800, 700x320에서 직책별 업무 화면을 검증했습니다.
- 글자 크기 150%, 긴 직원·지점·상품 이름, 데이터가 채워진 목록·그래프 조건을 포함했습니다.
- 대리점 직원과 점장의 일부 API 실패 상황에서 대시보드가 유지되는 회귀 테스트를 추가했습니다.
- 로그인·직원 등록의 작은 화면 검증도 포함했습니다.
- 대리점 직원·점장 화면을 태블릿 크기로 렌더링해 배치를 확인했습니다.
- 위 회귀 테스트와 렌더링은 검증용 데이터와 가짜 API를 사용했습니다. 모든 실제 직원 계정과 운영 서버에 대한 종단 간 검증을 의미하지는 않습니다.

7. 팀원이 프로젝트를 받을 때
- README.md의 초기 설정 및 실행 절차를 따릅니다.
- Flutter/Dart, Android SDK 등 개발 도구를 준비하고 flutter pub get을 실행합니다.
- 고객 앱과 동일한 Firebase 프로젝트에서 직원용 Android/iOS 앱 설정을 준비합니다.
- lib/firebase_options.dart, android/app/google-services.json, ios/Runner/GoogleService-Info.plist는 각자의 로컬에서 준비합니다.
- Firebase 구성 파일과 서버용 서비스 계정 비밀키, .env는 Git 업로드 대상이 아닙니다.
- 별도 shupick/backend의 호환되는 FastAPI 코드와 MySQL 스키마·마이그레이션이 필요합니다.
- 기존 DB에는 누락된 마이그레이션만 적용하며 데이터를 삭제하는 스키마 재생성 파일을 실행하지 않습니다.
- Android 에뮬레이터의 개발 서버 주소는 기본 http://10.0.2.2:8000입니다.
- 실제 태블릿은 API_BASE_URL에 기기에서 접근 가능한 서버 주소를 지정합니다.
- 직원 등록 또는 로그인 후 소속 지점·직책, 대시보드 새로고침, 각 업무 메뉴를 확인합니다.

8. 별도 프로젝트와 남은 작업
- Firebase 계정, MySQL 데이터, 백엔드 변경은 이 직원 앱 저장소의 git pull로 동기화되지 않습니다.
- 고객용 shupick 프로젝트에서 진행했던 직원 API, 직원·지점 DB 및 고객 화면 변경은 별도로 팀에 공유해야 합니다.
- 직원 간 업무 대화와 고객 혜택 승인은 DB/API가 없어 메뉴에 제공하지 않습니다.
- 본사 반품 검수 후 환불 실행, 제조사 실제 발주 연동, 수동 재고 조정 화면은 아직 구현하지 않았습니다.
- Firebase 설정 파일을 Git 추적에서 제거했지만 과거 커밋에 노출된 키는 기록에 남습니다. 키의 제한·교체 상태는 Firebase/Google Cloud에서 별도로 확인해야 합니다.
- 현재 직원 즉시 등록 정책은 테스트용이며 운영 전 등록·권한 부여 정책을 결정해야 합니다.

이 문서는 위 기준 시각까지의 진행사항을 기록한 스냅샷입니다.
